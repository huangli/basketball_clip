# basketball-clip 使用手册

> 面向普通用户的操作手册。整个流程就一句话：**机器干活，人做裁判**——机器把可疑片段排好序端到页面上，你按键拍板。
>
> **图形界面已可用**：`python -m gui` 起本地向导（选目录 → 设队名 → 检测 → 标注 → 认人 → 出合集 → 照片精选），每步有进度与失败提示；也可以完全用命令行 + 浏览器页面完成，本文以命令行为主线。

流程总览：

```
① score（检测，机器）→ ② 标注进球（浏览器，人工）→ ③ build（出片，机器）
                              ↓ 可选
              people（认人，机器+人工）→ build --all（实名合集）
                              ↓ 可选
              photo（精彩照片，机器+人工）
```

## 〇、命令卡（照抄即用）

```powershell
python scripts/video.py score "20260101_蓝队" --session 20260101_蓝队   # ① 检测：几个小时，挂着跑；跑完自动记住当前场次，后面命令都不用再写 --session
# ② 人工：浏览器标注（见下），点导出直接保存到场次目录（2026-09-13 起，无需再手动移动文件）
python scripts/video.py build                                           # ③ 出片：颜色分队集锦+每球独立片段+自动个人合集，成品在 output\20260101_蓝队\
# ④ 可选认人（要实名/分队合集才做）：
python scripts/video.py people --batch 1                                #   认人：机器几分钟；逐批跑（--batch 2、3……）
#   人工：浏览器确认认人，点导出直接保存到场次目录（2026-09-13 起，无需再手动移动文件）
python scripts/video.py build --all                                     #   认人后重跑出实名合集
python scripts/video.py photo                                           # ⑤ 照片（可选）：页面选完导出后加 --apply 落盘
```

- **换新场次**：score 换两处（素材目录名 + 场次 ID），跑完当前场次自动切到新场次，后续命令照旧不带 `--session`；场次 ID 规则 `日期_对手名`（如 `20260101_蓝队`）。素材目录名本身就符合场次 ID 规则时，score 的 `--session` 也能省（缺省取目录名）。
- **--session 都能省**：score 成功后把场次记进 `work\current_session.json`，people/build/photo 缺省读它；想临时操作别的场次，那条命令显式加 `--session <场次>` 即可（不会改动当前场次记录）。
- **中断/报错**：重跑同一条命令，已完成的阶段自动跳过。

## 一、新场次上手

### 第 0 步：素材就位

- 新视频放进一个独立目录，如 `20260101_蓝队\`（建议放仓库根下，名字随意）。
- 网盘下载的场次，先确认没有 `.baiduyun.p.downloading` 之类的未下完后缀文件——没下完的会被跳过或抽帧不全。
- 素材只进不出：流水线不删不改任何原始视频。

### 第 1 步：检测（机器）

```powershell
python scripts/video.py score "20260101_蓝队" --session 20260101_蓝队
```

- **场次 ID** 规则：`日期_对手名`，之后所有命令都用它。**score 成功后自动把本场记为当前场次**（存在 `work\current_session.json`），之后的 people/build/photo 都不用再写 `--session`。
- 全自动串联：探测规格 → 抽帧 → 双模型检测 → 候选挖掘 → 筐轨迹 → 切审核片段 → 生成标注页。CPU 检测约 1 秒/帧量级，整场要跑几个小时，挂着就行。
- **耗时参考**：抽帧（全场只跑一次）约几十分钟；之后每批（约 50 个文件）1～2 小时。耗时与素材量成正比，建议睡前挂上。
- 文件多会自动切批（batch1、batch2……），中断/报错后直接**重跑同一条命令**，已完成的阶段自动跳过。
- 想先看计划不动手：加 `--dry-run`；想全部重算：加 `--force`。

### 第 2 步：标注进球（人工）

1. 浏览器打开 `work\20260101_蓝队\review_batch1\label.html`（每批一个，batch2、batch3 同理）。
2. 片段自带 2 倍速烘焙，默认就是高效状态。逐条按键：

| 按键 | 含义 | 按键 | 含义 |
|---|---|---|---|
| <kbd>J</kbd> | 进球·**定锚** ✓：在**球入网瞬间**按下，按下时刻即成品片段锚点（前 4 后 2 围绕它切）。属疑似同回合组时弹窗询问，确定才把同组其余标 F 跳过 | <kbd>W</kbd> | 全景 / 筐区 视角切换 |
| <kbd>T</kbd> | 进球·**机器锚**：入网瞬间被挡/出画指不准时用，锚点取机器值（时机可能偏，能看清入网一律用 J） | <kbd>S</kbd> | 倍速切换（默认已是有效 2x） |
| <kbd>P</kbd> | 进球但不收（练球等） | <kbd>←</kbd> <kbd>→</kbd> | 上一条 / 下一条 |
| <kbd>F</kbd> | 不是进球 ✗ | <kbd>G</kbd> | 跳到下一个已标进球（补锚专用：G 定位 → 入网帧按 J → 再 G） |

> **提示**：片段会循环重播，等入网那帧转过来再按 J 即可，按早了/晚了再按一次就改锚（进度行显示 `锚 t=xx.xs（人工）`）。改标/补锚后页面**原地不动**（只有首次标注才自动跳下一条），配合 G 键逐个过进球。跨文件续接的片段（水印带"跨文件续接"）J 自动退化为机器锚，页面会提示。

3. 进度自动存在浏览器里，关了就下次接着标；各批页面进度互相隔离。
4. 标完点**导出**——文件由服务端直接保存到场次目录（`work\<场次>\goals_batchK.json`，2026-09-13 起），页面提示"已保存到 …"即可，**无需再手动移动**；若服务器不可达会回退为浏览器下载（此时仍需手动移到场次目录，页面会提示）。

### 第 3 步（可选）：认人（机器+人工）

**认人是可选项**：不认人也能直接出片（见第 4 步）。要**实名个人合集和分队集锦**才做这步。

```powershell
python scripts/video.py people --batch 1
```

- 机器自动：轨迹法定位投篮者 → 多裁选帧（**质量闸自动拦废帧**：畸形框/无人框）→ **轨迹传播**（同一段视频里同一人的连续在场轨迹互相预填——你认了一球，同轨迹的其他球自动预填同一人，逐球可改；不算进球不传播）→ CLIP 聚类分组 → 生成确认页。
- **球衣读号默认关**：想自动读号预填，加 `--read-numbers` 显式开（需先配置 VLM 凭证环境变量 `BASKETBALL_CLIP_VLM_TOKEN`，未配置会显式报错；结果按裁图缓存不重复扣费）。人脸匹配预填同样默认关（想试加 `--photo-match`，需额外安装 insightface，注意其权重为非商用许可）。
- **球员名单维护（一次配置长期受益）**：确认页可通过 `--players-file` 注入名单 JSON（号码=姓名一行一个），确认页按钮直接就是真人名，合集文件名也带上真名。
- 浏览器打开确认页 `work\20260101_蓝队\scorers_b1\scorer.html`：**看视频终裁，裁图只是辅助**。2026-10-19 起页面改为**簇优先单流**：默认进入簇审阅模式，一次按键处理一整簇，簇队列清空后自动进入逐球收尾。
  - **模式一：簇审阅**——当前簇独占画面：代表裁图墙 + 2x 片段自动播放 + 号码票/颜色多数票等元信息。按球员键（角标显示）即**整簇归属**并自动跳到下一簇；<kbd>Enter</kbd>（名单 ≤11 人时 <kbd>E</kbd> 同效）在簇内预填唯一多数且无歧义时采纳；<kbd>O</kbd> 整簇标为对手；<kbd>N</kbd> 整簇不算进球（二次确认）；<kbd>S</kbd> 跳过当前簇移到队尾；<kbd>X</kbd> 进入剔除子态，把聚类分错的球踢进残余池；<kbd>M</kbd> 进入合并子态，<kbd>←</kbd>/<kbd>→</kbd> 选目标簇后 <kbd>Enter</kbd> 合并（合并子态下其他按钮与球员键均不可用）。误操作按 <kbd>Z</kbd> 撤销（内存栈，刷新丢失）。
  - **模式二：逐球收尾**——簇队列清空后自动切换（也可按 <kbd>/</kbd> 手动往返），处理残余球、未入簇球、SKIP 球。这里保留 **全部 / 未归属 / 按球员** 过滤；<kbd>←</kbd>/<kbd>→</kbd> 翻球，球员键归属，<kbd>N</kbd> 不算进球，<kbd>S</kbd> 跳过。若未跑聚类（无 `--clusters`），页面直接进此模式。
  - **全局键位**——<kbd>P</kbd> 一键接受全场号码/照片预填（不标手改，后续仍可覆盖）；<kbd>Z</kbd> 撤销；<kbd>G</kbd> 展开名单表格；<kbd>/</kbd> 切换模式；<kbd>Enter</kbd>/<kbd>E</kbd> 采纳当前预填。所有快捷键在输入框/下拉框/选择框聚焦时自动屏蔽。
- 有号码/照片预填时**建议进页先点顶栏「接受全部号码预填」**（只是预填不是终裁，照样能改；歧义球自动跳过）。黑球衣球可点**「接受全部对手预填」**一键归到对手；轨迹传播预填不走一键全收、逐球自动生效。
- 名单表格内联改姓名/改队；顶部对手队名输入框可覆盖自动派生值。
- 确认完点导出——`roster.json` 由服务端直接保存到场次目录（2026-09-13 起），**无需再手动移动**；服务器不可达时回退为浏览器下载（此时仍需手动移入，页面会提示）。
- 然后跑下一批 `--batch 2`、`--batch 3`——后一批会自动带上已有 roster 预填，越跑越省劲。**建议逐批跑、逐批确认。**
- **对手队名自动取场次名后缀**（如 `20260101_蓝队` → 蓝队），也可在 `work\<场次>\team_config.json` 里显式配置队名（见 README 配置节）。

> **提示**：预填（聚类分组、轨迹传播、读号、颜色分队）都可能错，一律可一键改；球衣互换时读号必错，以画面为准。

### 第 4 步：出片（机器）

```powershell
python scripts/video.py build
```

- **没认人（或认人没确认导出）也能直接出片**，一条命令出三样：
  `队伍_黑_进球集锦.mp4` / `队伍_白_进球集锦.mp4`（按球衣颜色自动分队，**允许分错**——撞色/便服多的场次会分不准）、
  `进球片段\`（每个进球一个独立 mp4，直接翻看/分享）、
  `黑_A_进球合集.mp4` 等（机器自动聚类分组到个人）。要准的实名合集就走第 3 步认人后重跑。
- 认人后（roster.json 已确认导出）用 `--all`：roster 里逐人出个人合集 + 逐队出队伍集锦（便服队自动跳过）。多批次场次自动合并跨批片段；某球员或某队伍在选定批次里没球会 WARNING 跳过，不中断其他人。
- 只要单人：`--scorer 红队-7号`；只要单队：`--team 红队`（均需已认人）。只看某一批：加 `--batch 2`。
- 成品在 `output\20260101_蓝队\`：认人后队伍 `队伍_XX_进球集锦.mp4`、个人 `<队伍>_<姓名>_进球合集.mp4`，片段按拍摄时间排序。
- **认人后合集合成完会自动出进球热图**（同目录，每队两张）：`队伍_XX_进球热图.png`（暗场热力图）+ `队伍_XX_进球热图_分区.png`（分区统计）。没认过人不出热图只出合集；热图出岔子不影响合集本身。
- **4K**：主队（team_config 里的 team_name）队伍集锦默认 4K（16:9 场次 3840×2160，4:3 场次 2880×2160），其余产物维持 1080p。要某个合集单独出 4K：加 `--4k`（如 `--scorer 红队-7号 --4k` / `--all --4k`），产物名加 `_4K` 后缀并与 1080p 版本并存；主队集锦对 `--4k` 为 no-op（本已默认 4K）；未认人自动模式忽略 `--4k`。
- **耗时**：分钟级。每球切一条 6 秒片段并重编码到 1080p（4K 步骤约为 1080p 的 3~4 倍耗时），球越多越久。
- **注意**：goals 或素材变更后重跑 build，自动聚类用的裁图产物不会自动更新——把 `work\<场次>\scorers*` 目录删掉再重跑即可。

### 第 5 步（可选）：精彩照片（机器+人工）

```powershell
python scripts/video.py photo
```

- 机器自动：用检测缓存打分（球速/人球交互/主体大小/球高度）→ 时间分桶选约 200 张 → 抽帧防抖 + 自动构图裁切放大（可断点续跑）。
- 浏览器打开 `work\20260101_蓝队\photos\photo_page.html`：瀑布流点选（再点取消），双击看原图，<kbd>←</kbd><kbd>→</kbd>/数字键翻页，<kbd>A</kbd> 全选本页，回车导出。
- 导出得到 `photo_selections.json`，**移动**到 `work\20260101_蓝队\photos\`，然后落盘：

```powershell
python scripts/video.py photo --apply
```

- 成品在 `output\20260101_蓝队\照片精选\`：`照片_XXX_视频序号_时刻.jpg`（1080p，比例跟随素材）。

## 二、命令速查

| 命令 | 干什么 | 常用参数 |
|---|---|---|
| `score <目录>` | 检测链路，一路跑到生成标注页（整场小时级，可断点续跑） | `--session` 可省（缺省=素材目录名；成功后记为当前场次）；`--dry-run` 只打印；`--force` 全部重算；`--batch-size` 每批文件数；`--fids` 补跑指定文件 |
| `people` | 认人链路：裁图 → 聚类 → 确认页（机器每批几分钟） | `--session` 可省（缺省=当前场次）；`--batch K` 指定批次（建议逐批）；读号默认关，`--read-numbers` 显式开；人脸预填默认关，`--photo-match` 显式开；`--players-file` 注入名单 |
| `build` | 合成合集（认人后另出进球热图，暗场/分区双图） | `--session` 可省；默认出颜色分队集锦+进球片段+自动个人合集（无需认人）；认人后 `--all` 全量 / `--scorer` 单人 / `--team` 单队；`--4k` 手动重出所选产物为 4K（加 `_4K` 后缀） |
| `photo` | 精彩照片：打分 → 候选页 → `--apply` 落盘 | `--total` 候选张数；`--apply` 按导出选择落盘 |
| `clean` | 清场等下一场：清空 output、work、源视频目录（**全部场次一起，不分场次**） | 先 `--dry-run` 看清单；真跑需键盘输入 `yes` 确认；**源视频删了不可恢复** |

> **注意**：`clean` 不分场次、全部清空：output 里所有场次的成品合集、work 全部中间产物、源视频目录一起删，删了不可恢复。**成品发出去之前别 clean。**

## 三、文件都放哪

| 位置 | 内容 |
|---|---|
| `20260101_蓝队\`（素材目录） | 原始视频，处理时只读不动；`clean` 确认后会整目录删除 |
| `work\20260101_蓝队\` | 本场全部中间产物：goals_batchK.json（你标注的）、roster.json（你确认的）、candidates_batchK.json / review_batchK / scorers_bK（机器的）、scorers_auto / auto_roster.json（未认人自动合集用的聚类产物） |
| `work\frames\`、`work\detect\` | 抽帧与检测缓存（跨批共享，断点续跑靠它们） |
| `work\current_session.json` | 当前场次指针（score 成功后写入；clean 会一起清） |
| `output\20260101_蓝队\` | 成品合集（认人后另有进球热图）；未认人时的每球独立片段在 `进球片段\` 子目录 |

## 四、成品规格（已定型，不用管）

- 进球锚点 = 球入网瞬间；片段窗口 = 前 4 秒 + 后 2 秒。
- 输出 1080p / 50fps / H.264 + AAC；比例跟随素材等比缩放：16:9 出 1920×1080，4:3 出 1440×1080。**主队队伍集锦默认 4K**（16:9 场次 3840×2160，4:3 场次 2880×2160），其余产物维持 1080p。
- 100fps 素材：入网后 2 秒半速慢放，与常速段拼接；其他帧率不慢放。
- 命名用真名，未填真名回退标签：`红队_张三` / `红队-7号`、`黑T恤-A` 风格；未认人的自动合集用颜色队+簇标签：`黑_A`、`白_B`……

## 五、常见问题

### 跑了一半中断了 / 报错了

重跑同一条命令。已完成的阶段（抽帧、检测、候选……）会自动跳过，从断点继续。

### 日志里出现 `零候选 fid（缓存正常，正常产出）`

正常现象。个别短片段（几秒到十几秒）全程没有可疑球轨迹，算法一个候选都不产，这些片段不进标注页——它们本来也没有值得看的球。

### 报错 `fid 覆盖不足`

检测缓存缺失或失效，属真异常。请到 GitHub 仓库提 issue 并附完整报错。

### 报错 `混合分辨率 / 混合帧率`

同一场次目录里混了不同规格的素材（如 16:9 和 4:3）。把不同规格的分开，各自声明场次分别跑。

### 想出实名合集但 roster 未确认

认人是可选项：**没认人不会被拒**，build 会直接按球衣颜色分队出队伍集锦（黑/白，便服不出）+进球片段+自动个人合集。只有认人后用 `--all`/`--scorer`/`--team` 出实名合集时，才需要确认页导出的 `roster.json` 已位于 `work\<场次>\` 下。

### 报错 `--session 未给且无当前场次记录`

当前场次记录（`work\current_session.json`）还没有或被清掉了（`clean` 会一起清）。先跑一场 score 即自动重建；或者在这条命令上显式加 `--session <场次>`。

### 往已跑过的场次里补新视频

```powershell
python scripts/video.py score "素材目录" --session 已存在场次 --fids 新视频fid1,新视频fid2
```
